# 音乐平台插件化改造计划

## 目标

飞牛音乐、网易云音乐、Songloft、Subsonic 和 QQ 音乐各有一个完整的插件目录。每个插件拥有整套界面、平台业务和播放控制策略。宿主只提供窗口运行、音频播放、存储、网络和插件生命周期等底层能力。

升级前后，用户使用同一份数据启动应用，应看到相同的界面，用相同的操作得到相同的结果。文案、布局、动画、导航、焦点、快捷键、平台切换、账号与播放恢复都以改造前的实际行为为准。

首期使用仓库内的 Go 源码插件，由应用入口显式装配并随桌面应用一起构建。Subsonic 插件保留 Navidrome、Jellyfin、Gonic 和通用 Subsonic 四个现有入口，各入口继续使用原有的平台 ID、配置、凭据和运行状态。

## 改造前的结构

- 飞牛、Songloft、Subsonic 和 QQ 音乐的页面与协议客户端原先分布在 `internal/app/platform/` 和 `internal/platform/`。主窗口当时挂载各平台的侧栏与内容区，底栏、正在播放和部分弹窗仍由 `app` 绘制。[当前整窗挂载](../../internal/app/plugin_window.go)
- 网易云首页、导航、账号、推荐、播客和心动模式散在 `internal/app/`，协议代码在 `internal/netease/`。启动、页面路由和播放仍包含网易云的特殊分支。[应用启动](../../internal/app/app_platform.go) · [网易云登录与会话恢复](../../internal/plugins/netease/ui_account.go) · [播放器回调](../../internal/player/player_platform.go)
- 旧版 `Host` 同时暴露播放命令和列表、卡片、搜索、封面、设置等渲染方法。旧版适配器通过 `ConfigurePlayer(*player.Player)` 改写播放器回调，公共曲目和音源类型来自网易云包。音频缓存原先使用数字曲目 ID 加音质查找。[当前插件接口](../../internal/pluginapi/platform.go) · [缓存实现](../../internal/player/cache.go)

## 宿主和插件的职责

| 范围 | 宿主提供的底层能力 | 插件拥有的界面与业务 |
| --- | --- | --- |
| 窗口与事件 | 创建、显示、隐藏、关闭和刷新窗口，传递系统主题、屏幕和原生事件 | 主窗和各独立窗口的根视图，布局、标题栏、背景、边距、主题配色、焦点、动画和快捷键绑定 |
| 菜单与浮层 | 安装由插件提供的原生菜单和托盘内容，执行剪贴板等系统操作 | 平台切换器、账号菜单、右键菜单、弹窗、Toast、应用菜单、托盘菜单、桌面歌词和刘海播放器 |
| 播放 | 播放命令与状态、队列执行、解码、缓冲、跳转、音量、淡入淡出、EQ、MPV、DLNA、媒体键 | 底栏、正在播放、进度条、队列、投播、音效设置及交互。选择曲目、生成队列、分页续队、电台续播、取流、音质与转码策略、播放上报 |
| 资源 | HTTP 和代理基础设施、缓存、图像解码、歌词解析和时间轴 | 登录鉴权、请求签名、封面与歌词获取、资源引用解析、播放历史、收藏、歌单、搜索、目录、推荐、播客和评论 |
| 生命周期与数据 | 注册和切换插件、主线程调度、存储和安全凭据、现有播放会话的持久化 | 平台配置结构、默认值与校验、账号连接和重连、路由历史、视图状态、业务状态及自有任务的清理 |

插件直接用 MyGo 绘制界面，向宿主提交根视图、窗口选项和原生菜单内容。宿主按照插件提交的内容接入系统窗口与事件。原来的 `RenderTracks`、`RenderCards`、`RenderSearch`、`SharedSettings`、`NowPlaying` 等项目内渲染入口，迁移后由各插件自己的代码实现。共用过的组件、样式、图标、文案、动效和输入处理按各平台当前用法逐份复制，副本由各插件独立维护。Subsonic 的四个入口在同一个插件里沿用现有实现。

例如，进度条的命中区域、拖动反馈和松手时机随视图迁入插件，插件在同一交互时机调用宿主的 `Seek`。飞牛插件创建、获取和释放 HLS 会话，宿主读取分段并完成解码和跳转。设置页面由插件完整绘制，音量、主题等设置仍读写原先对应的全局值，已有平台专属选项继续落在原有作用域。

## 公共接口与数据归属

- 每个平台通过一个 `Start` 入口加载。入口接收宿主服务，为每个窗口注册完整的根视图、原生选项及所需的生命周期回调，并提供原生菜单。宿主在第一帧前加载实例，按窗口 ID 挂载根视图并管理原生窗口生命周期。侧栏、内容区、底栏及浮层的组合、绘制、交互和状态都由插件处理，注册契约的粒度是整窗。随平台切换的独立窗口在卸载时解除事件订阅，由宿主销毁。
- 每个插件提供主窗口，其余窗口按需注册。宿主保留两边都提供的主窗、设置窗和桌面歌词窗，在原生窗口创建时应用注册的选项，在平台切换时替换整窗根视图并隔离控件输入。切到缺少设置窗或桌面歌词窗的插件时，宿主关闭相应窗口并释放监听。独立辅助窗口随插件激活而创建，可以通过 `Mount` 注册原生事件及清理函数。
- `Playback` 提供播放、暂停、跳转、队列替换与追加、播放状态读取等操作。插件通过解析回调返回直连或分段音源、必要的请求头和音频元数据。宿主传入解码或输出方式等必要信息，插件据此应用其已有策略。
- 公共曲目、音源和封面引用放在 `pluginapi`。新增资源引用按「平台实例 ID + 平台原始资源 ID」定位，原始 ID 可以是字符串。音频缓存同时区分音源规格。取流、歌词、封面、投播预取及播放回调按资源归属分发。收藏、评论、详情跳转等继续由绘制该界面的插件调用自己的业务实现。
- 文件、凭据和设置服务提供实例作用域，同时兼容现有全局键、平台专属键和历史文件。历史设置和播放会话继续按原有格式读取。旧音频缓存只记录数字 ID、音质和音源元数据，多个平台可能产生相同数字 ID。首次播放先向所属插件解析音源。有内容摘要时，播放器根据当前音源的格式和音质定位旧文件，校验完整音频后迁入当前实例的缓存，后续可在离线时读取。摘要缺失或匹配失败时，旧文件仍按原缓存容量策略管理，播放继续使用解析出的音源。[缓存验证与迁移](../../internal/player/cache.go)
- 各插件定义自己的设置类型和默认值，通过 `SettingsStore` 读取和保存该实例的序列化记录。已有嵌套设置沿用插件声明的旧键，旧版顶层设置只读写插件明确声明的字段。新增插件直接使用 `plugins.<id>`，添加字段只需要修改该插件。账号凭据继续由独立的凭据服务处理。[设置存储契约](../../internal/pluginapi/settings.go) · [旧键读写回归](../../internal/app/legacy_preferences_test.go)
- 页面请求和播放器任务分别绑定对应的实例与生命周期。切换时取消旧页面任务，在主线程应用结果前校验来源。播放器仍按生产代码现有规则停止播放、清空队列并丢弃旧播放会话。应用重启则沿用原有的恢复条件和恢复时机。[切换逻辑](../../internal/app/settings_platform.go) · [播放会话](../../internal/app/session.go)

```mermaid
flowchart LR
    A[应用装配内置插件] --> B[插件 Start 接收底层服务]
    B --> C[插件注册整窗根视图和菜单]
    C --> D[宿主按窗口 ID 挂载根视图]
    D --> E[插件根视图组合侧栏和页面等区域]
    E --> F[插件处理操作并调用播放等服务]
```

`Start` 是宿主加载一个平台时调用的入口。宿主把插件注册的完整根视图交给窗口系统，之后由该根视图接管每一帧的布局、绘制和输入。`DrawSidebar` 这类局部绘制方法，以及侧栏、内容区、底栏和弹窗之间的调用顺序，全部留在插件内部。新增平台提交自己的根视图和原生窗口选项，宿主沿用同一条挂载路径。[整窗挂载](../../internal/app/plugin_window.go) · [飞牛窗口入口](../../internal/plugins/fnmusic/window.go) · [网易云窗口入口](../../internal/plugins/netease/window.go)

每个插件按现有代码量组织 `plugin.go`、`window.go`、`navigation.go`、`player_bar.go`、`now_playing.go`、`settings.go`、`widgets.go` 等文件。协议代码量较大时收在该插件自己的 `internal/client/`，测试和平台专用资源随功能迁入。

`builtin` 显式导入插件。宿主通过 `pluginapi` 挂载窗口并分发媒体请求。插件访问项目底层服务与通用算法的依赖都位于 `pluginapi`，界面直接使用 MyGo。各平台自己实现登录、收藏、评论和页面路由。

新增平台时，在自己的目录实现 `Start` 和注册声明，再加入内置装配。平台 ID、显示名、图标、开发者模式可见性和旧设置键由各插件声明。`pluginapi.ID` 是通用类型。插件从宿主取得注册信息并自行绘制平台选择器。启动优先恢复已保存且能打开的插件，首次启动选择内置默认平台 `fnmusic`。内置顺序沿用现有平台选择顺序，无效切换请求沿用旧应用的回退规则。旧平台使用各自声明的旧设置键，新增平台默认使用 `plugins.<id>` 设置空间。[插件注册契约](../../internal/pluginapi/platform.go) · [内置装配](../../internal/builtin/platforms.go)

平台界面、点击与快捷键、登录、搜索、歌单、续队及帧预算测试随实现放在各自的 `internal/plugins/<id>/`。协议测试与请求样例放在插件自己的 `internal/client/`。`internal/app` 用模拟插件验证窗口挂载、平台切换、旧设置读写和播放归属。跨平台测试夹具位于 `internal/plugins/internal/plugintest`，由各插件在自己的测试中使用。[宿主整窗测试](../../internal/app/plugin_window_test.go) · [网易云帧预算测试](../../internal/plugins/netease/perf_test.go) · [Songloft 窗口测试](../../internal/plugins/songloft/registered_window_test.go)

## 实施顺序

1. **记录迁移基线。** 使用相同数据、窗口尺寸和主题记录各平台主窗、设置、底栏、正在播放、遮挡恢复、加载和错误状态。记录桌面歌词、刘海、托盘、快捷键和窗口关闭后继续播放的入口。保留可重复使用的旧版设置和会话样例。
2. **接入无界面宿主接口。** 以现有启动和播放链路为基线，引入根视图安装、实例调度、播放命令和音源解析契约。兼容现有曲目与音源数据，逐步把取流、歌词、封面和投播预取改为按归属分发。同步核对缓存查询、写入及投播取本地文件的路径。
3. **用 Songloft 完成第一条完整链路。** 把平台页面、连接、文件夹、检索、歌单、收藏、队列和歌词迁入同一目录。把它当前使用的主窗、设置、播放和独立浮层视图连同输入处理复制到插件内。验证从旧版数据启动、操作主窗、播放到关闭和重开的全过程，用实际调用收敛接口。
4. **逐个迁移飞牛、Subsonic 和 QQ 音乐。** 飞牛重点验证 HLS 会话释放、格式兼容和漫游续队。Subsonic 验证四个入口的配置、账号、原始 ID、封面、缓存和历史归属。QQ 音乐验证登录、音质、搜索建议、评论与开发者模式入口。每个平台完成整套迁移后单独对照验收。
5. **迁移网易云并收口。** 把网易云页面、侧栏、登录、弹窗、推荐、播客、评论和心动模式与协议代码一起迁入插件。将网易云纳入统一注册和资源分发。待所有平台都通过回归后，删除旧的公共渲染入口、旧平台注册分支和播放器中的网易云回退。

## 验收标准

- **界面一致。** 对照各平台升级前后的首页、导航、设置、列表、底栏和正在播放，核对布局、样式、文案、加载、空状态和错误状态。桌面歌词、刘海、托盘与原生菜单在适用桌面环境验证。按项目约定用 `NM_FRAMES` 输出 PNG 做人工对照。
- **操作一致。** 验证返回与前进、列表滚动位置、菜单与弹窗、键盘焦点、Space、拖动进度、切歌、收藏、歌单编辑、电台或漫游续播、投播及关闭窗口后继续播放。加载和空闲帧预算沿用 `perf_test.go` 的行为验证。[测试约定](../../AGENTS.md) · [现有帧预算测试](../../internal/plugins/netease/perf_test.go)
- **升级无感。** 用旧版数据启动，验证已选平台从第一帧生效，账号、设置、窗口位置、缓存和原有的播放恢复规则生效。核对开发者模式、平台切换时的队列清理，以及旧平台请求晚到时界面的隔离行为。
- **依赖边界成立。** 具体平台实现集中在该插件目录。宿主通过注册和底层接口工作，所有项目视图由插件提供。用跨实例相同曲目或封面 ID、切换后的迟到结果、旧数据读取来验证可发生的回归。每个迁移阶段运行 `go test ./internal/...`，新增 UI 测试按项目约定用 `-count=5` 验证。

五个平台及 Subsonic 的四个入口都通过视觉、操作和升级回归后，改造完成。

## 当前实施状态

播放会话服务通过 `Activate` 交给本次激活的插件，用于读取旧会话、恢复队列、接入电台续播和读取音频。切出后旧调用失效，切回同一插件时也只有新激活周期可以操作。回归同时验证旧延迟任务不会写回会话文件。调整后在 Linux 原生窗口重新验证了网易云旧队列暂停恢复，以及禁用远程音源查询后重启仍从本地缓存恢复。[会话归属与旧队列恢复回归](../../internal/app/session_test.go)

五个平台的设置模型已各自放入插件目录。Subsonic 四个入口的回归用例验证了重连时把保存的转码模式和码率应用到客户端，并将修改写回当前入口。Linux 原生启动对照还验证了网易云的旧版音质和字幕偏好可读取，后台提交的归一化偏好可在重启后恢复，共享音量保持原值。[Subsonic 账号和转码回归](../../internal/plugins/subsonic/credentials_test.go) · [网易云设置模型](../../internal/plugins/netease/preferences.go)

在 Linux 原生窗口中使用旧版数据目录和模拟网易云服务完成了两次启动。首次使用旧 Cookie 请求账户和音源，在 1.25 秒处暂停恢复。跳到 2.5 秒后退出，再启动从本地音频缓存恢复到 2.5 秒，保留队列顺序、随机播放和循环模式。
